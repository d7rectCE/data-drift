# Путеводитель для отчёта по проекту

Этот файл — карта репозитория под написание отчёта: что делалось, в каком порядке, где
лежат цифры и графики и какие формулировки они выдерживают. Подробности каждого
эксперимента — в `README.md`, полные таблицы — в `results/expN_tables.md`, код экспериментов —
в `experiments/expN_*.py` (в начале каждого файла docstring с постановкой).

## Логика проекта в одном абзаце

Практические детекторы дрейфа (Page-Hinkley, DDM, ADWIN, KS) выдают бинарный сигнал с неизвестной
долей ложных тревог. Мы превращаем их в непрерывный скор, калибруем его бутстрепом в p-значение с
учётом автокорреляции и подаём p-значения многих моделей в процедуры контроля ошибок (Бонферрони,
BH, онлайн-FDR). Главные выводы: калибровка делает долю ложных тревог управляемой и сама даёт
основной выигрыш; FDR-адаптивность выигрывает у простого Бонферрони только при массовых
(кластерных) дрейфах; на реальных нестационарных данных вопрос «есть ли дрейф» надо заменить на
«стала ли модель существенно и надолго хуже», иначе почти все тревоги формально ложные.

## Ключевые цифры (все проверены по таблицам)

**Калибровка (эксп. 1, φ = 0.5, номинал 0.05):** iid-бутстреп 0.20–0.75; блочный 0.06–0.12;
AR-sieve 0.06–0.08. Пороги river по умолчанию: FAR от 0 до 0.83 в зависимости от детектора и φ.
При едином FAR ≈ 0.05 мощность в первом окне после сдвига на 1σ: ADWIN 0.99, PH 0.83, KS 0.33, DDM 0.26.

**Масштабирование (эксп. 2, PH, ρ = 0.3):** без поправки FDR ≈ 0.81 при любом K, 6 ложных
переобучений на окно при K = 500. Любая поправка экономит 5–6 ложных переобучений на реальный
дрейф ценой 20–35 шагов деградации за каждое (K = 500).

**Граница компромисса (эксп. 3):** при равном числе ложных переобучений онлайн-FDR не лучше
порога на поток, масштабированного под K (при K = 500: 265 шагов задержки против 324 у LORD++).

**Кластерные дрейфы (эксп. 4):** BH в окне быстрее лучшего фиксированного порога на 16–22%
в 7 из 8 ячеек; при разрозненных дрейфах выигрыша нет.

**Зависимость (эксп. 5):** дисперсия/среднее числа ложных тревог в окне 1 → 6–29 (ρ = 0.3) →
50–230 (ρ = 0.9). Потолок выигрыша от учёта зависимости при ρ = 0.3 — в 1.3–1.7 раза по уровню.

**Хвост калибровки (эксп. 6, 10):** Бонферрони при K = 100 даёт 0.09 (PH) и 0.25 (ADWIN) вместо
0.05; учёт неопределённости параметров снижает до 0.077 и 0.18. Итог эксп. 10 — см. README.

**Реальные данные (эксп. 7):** INSECTS, 50 моделей: доля ложных 75% (river) → 15% (калибровка) →
1–3% (калибровка + поправка). Electricity: около 97% у всех правил в постановке «есть ли дрейф».

**Существенное ухудшение (эксп. 8, 9):** INSECTS 0.7–1.3%, Electricity 0.25–0.35 (с устойчивостью
m = 3 — от 0 до 0.27, результат шумный).

## Формулировки, которые результаты выдерживают, и которые нет

Выдерживают:
- калиброванные p-значения делают долю ложных тревог управляемой, а пороги по умолчанию — нет;
- поправка на множественность окупается против текущей практики почти при любой разумной цене
  переобучения;
- FDR выигрывает у Бонферрони при кластерных дрейфах и не выигрывает при разрозненных;
- на нестационарных данных нужна нулевая гипотеза существенного ухудшения.

Не выдерживают (не писать без оговорок):
- «метод контролирует FDR строго» — хвост калибровки ошибается в 1.5–3 раза, у ADWIN сильнее;
- «метод работает на любых реальных данных» — проверены два набора, на Electricity результат шумный;
- «FDR лучше Бонферрони» без условия про кластерные дрейфы;
- любые утверждения о продовой эффективности — проверки на продовых логах не было.

## Ограничения, которые стоит назвать в отчёте

- Основные выводы на синтетике; реальных наборов два, из них размечен один (и то неполно).
- AR-sieve бутстреп на AR-синтетике корректно специфицирован, точность оптимистична.
- ADWIN реализован приближённо, KS — пакетный, а не инкрементальный.
- Гарантии онлайн-FDR выведены для независимых p-значений; у нас они зависимы.
- Модели на реальных данных не переобучаются по-настоящему: «переобучение» — это сбор нового
  опорного отрезка для той же модели.
- В экспериментах 4–10 от 3 до 60 повторов; где интервалы широкие, это сказано в README.

## Воспроизводимость

Все эксперименты запускаются командами из README «Быстрый старт», используют фиксированные
сиды и пишут результаты в `results/`. `pytest` проверяет совпадение детекторов с river, корректность
бутстрепа, калибровки, FDR-процедур, метрик и эквивалентность потоковой и пакетной версий.

## Словарик

| Термин | Смысл |
|---|---|
| FAR | доля ложных тревог на один тест (окно × модель) |
| FDR / FDP | доля ложных среди всех тревог (ожидаемая / в конкретном прогоне) |
| FWER | вероятность хотя бы одной ложной тревоги (здесь — в окне) |
| MDR | доля пропущенных дрейфов |
| MTD / задержка | время от начала дрейфа до тревоги |
| «шагов на старой модели» | задержка, где пропуск считается до конца потока — цена задержки |
| опорный отрезок | данные сразу после (пере)обучения, с которыми сравнивается новое |
| горизонт | сколько последних окон детектор видит при проверке |
| допуск δ | насколько ошибка может вырасти, не считаясь существенным ухудшением |
| кластерный дрейф | дрейф, одновременно затрагивающий много моделей |
