# driftfdr — контроль ложных тревог при мониторинге дрейфа во множестве ML-моделей

MVP исследовательского проекта: надстройка над практическими детекторами дрейфа
(Page-Hinkley, DDM, ADWIN, KS), которая превращает их бинарные сигналы в
статистически валидные p-значения и подаёт их в процедуры онлайн-контроля
доли ложных обнаружений (FDR). Цель — понять, когда такая надстройка
окупается: сколько лишних переобучений она экономит и какой ценой в задержке
обнаружения.

```
поток K ─► детектор (скор) ─► бутстреп-калибровка ─► p-значение ─┐
поток 2 ─► детектор (скор) ─► бутстреп-калибровка ─► p-значение ─┼─► онлайн-FDR ─► переобучить?
поток 1 ─► детектор (скор) ─► бутстреп-калибровка ─► p-значение ─┘
```

## Быстрый старт

```bash
pip install -e ".[dev]"      # numpy, scipy, pandas, matplotlib; для тестов pytest и river

python experiments/exp1_calibration.py   # ~15 мин на 4 ядрах, флаг --quick для пробы
python experiments/exp2_scaling.py       # ~15 мин
python experiments/exp3_tradeoff.py      # ~10 мин
```

Результаты пишутся в `results/` (CSV, таблицы в Markdown) и `results/figures/`.

Минимальный пример:

```python
from driftfdr import (
    CalibrationConfig, MonitorConfig, PageHinkley, ScenarioConfig,
    make_procedure, make_scenario, run_monitor, summarize,
)

# 200 моделей, у 10% из них в случайный момент растёт ошибка
scenario = make_scenario(ScenarioConfig(n_streams=200, phi=0.5, rho=0.3, drift_fraction=0.1), seed=0)
config = MonitorConfig(n_ref=300, window=100, horizon=5,
                       calibration=CalibrationConfig(n_boot=500, method="sieve"))

cache = {}  # калибровки переиспользуются между процедурами
for name in ["uncorrected", "LORD++"]:
    result = run_monitor(scenario, PageHinkley(), make_procedure(name, alpha=0.05), config, cache=cache)
    s = summarize(result)
    print(f"{name:12s} тревог={s['alarms']:4d} ложных={s['false_alarms']:4d} "
          f"FDP={s['fdp']:.2f} задержка={s['mean_delay']:.0f}")
```

```
uncorrected  тревог= 119 ложных=  99 FDP=0.83 задержка=121
LORD++       тревог=  20 ложных=   0 FDP=0.00 задержка=441
```

## Как это устроено

### 1. Детектор как непрерывный скор (`detectors.py`)

У каждого практического детектора один гиперпараметр чувствительности: λ у
Page-Hinkley, число сигм у DDM, δ у ADWIN, α у KS. Детектор срабатывает ровно
тогда, когда внутренняя статистика пересекает порог, заданный этим
гиперпараметром. Значит, бинарный сигнал — это пороговая версия непрерывного
*скора*, и скор равен «минимальной чувствительности, при которой детектор бы
сработал»:

| Детектор | Скор | Порог river по умолчанию |
|---|---|---|
| Page-Hinkley | `m_t − min m_s`, кумулятивное отклонение от среднего | λ = 50 |
| DDM | `(p_t + s_t − p_min) / s_min` | 3 |
| ADWIN | `−ln δ*`, где δ* — наименьшее δ, при котором есть разрез окна | `−ln 0.002` |
| KS | статистика Колмогорова–Смирнова «опорный отрезок vs новые данные» | критическое значение при α = 0.05 |

Page-Hinkley и DDM воспроизводят `river` точно: момент первой тревоги совпадает
на всех тестовых потоках (`tests/test_detectors.py`). ADWIN использует критерий
разреза из river на фиксированной геометрической сетке точек разреза вместо
экспоненциальной гистограммы и срабатывает в пределах `clock = 32` шагов от river.
Все скоры векторизованы по первой оси, так что тысячи бутстреп-реплик
обрабатываются одним вызовом.

Почему не работать с бинарным сигналом напрямую: чёрный ящик с одним порогом даёт
p-значение из двух значений `{q, 1}`, где q — вероятность тревоги при нуле. Онлайн-процедуры
FDR при сотнях потоков требуют уровней 1e-4…1e-7, до которых такое p-значение не
дотягивается никогда.

### 2. Схема теста (`monitor.py`)

Время делится на окна по `window` шагов (по умолчанию 100). У каждого потока есть
опорный отрезок из `n_ref` шагов (300), собранный сразу после последнего
(пере)обучения. В конце каждого окна детектор прогревается на опорном отрезке и
прогоняется по последним `min(прошло, horizon)` окнам (горизонт — 5 окон);
статистика теста — максимум скора в текущем окне. Горизонт позволяет свидетельству
копиться, как у детектора, работающего в продакшене непрерывно; без него онлайн-FDR
не находит почти ничего (см. «Что показал MVP»). После тревоги поток переобучается,
следующие `n_ref` шагов собирается новый опорный отрезок, и поток в это время не
мониторится.

Нулевая гипотеза задаётся через режимы: тест нулевой, если среднее потока постоянно
на всём отрезке от начала опорного отрезка до конца окна. Это синтетическая версия
«режимного» определения нуля из заявки.

### 3. Калибровка в p-значение (`calibration.py`, `bootstrap.py`)

Нулевое распределение статистики оценивается по B = 500 бутстреп-рядам,
ресемплированным из опорного отрезка: и псевдо-опорный отрезок, и псевдо-новые
данные, чтобы их взаимная изменчивость соответствовала реальному тесту. Скоры
каузальны, поэтому один прогон по ряду длины `n_ref + horizon·window` даёт нулевые
распределения сразу для всех длин горизонта: одна калибровка на опорный отрезок.

Схемы ресемплинга: блочный бутстреп Кюнша (`moving`), стационарный бутстреп
Политиса–Романо (`stationary`), AR-sieve бутстреп Бюльмана (`sieve`) и обычный
iid-бутстреп как контроль. Длина блока выбирается по формуле Политиса–Уайта для
AR(1)-приближения, порядок AR — по AIC.

p-значение — `(1 + #{T* ≥ T}) / (B + 1)`. Его минимум 1/(B+1) ≈ 0.002 слишком велик
для онлайн-FDR, поэтому когда превышений меньше 10, p-значение экстраполируется по
экспоненциальному хвосту, подогнанному к верхним 10% бутстреп-выборки (подход
Knijnenburg et al., 2009). Экспоненциальный, а не GPD, потому что статистики здесь —
максимумы сумм и квадратов стандартизованных разностей (домен Гумбеля), а оценка
параметра формы GPD по 50 точкам слишком шумная. GPD доступен как `tail="gpd"`.

### 4. Правила принятия решений (`online_fdr.py`)

| Правило | Что контролирует |
|---|---|
| `uncorrected` | каждый поток на уровне α — текущая практика |
| `bonferroni` | α/K в каждом окне: вероятность хотя бы одной ложной тревоги в окне |
| `bh_window` | Бенджамини–Хохберг внутри окна: FDR в каждом окне |
| `LOND` | онлайн-FDR, устойчив к положительной зависимости (PRDS) |
| `LORD++` | онлайн-FDR, «богатство» пополняется при каждом открытии |
| `SAFFRON` | онлайн-FDR, адаптируется к доле нулевых гипотез |
| `alpha-investing` | mFDR, Foster–Stine |
| `raw` | детектор river с порогом по умолчанию, без калибровки |

Онлайн-правила получают гипотезы окна в случайном порядке, не зависящем от p-значений.

### 5. Данные и метрики (`streams.py`, `metrics.py`)

K потоков — сигналы ошибок K моделей: AR(1) во времени с коэффициентом φ и общим
фактором между потоками с корреляцией ρ. У доли потоков в известный момент среднее
сдвигается резко или постепенно (в единицах стандартного отклонения). Из того же
латентного процесса строится бинарный сигнал ошибок для DDM (базовая доля ошибок 0.2).

Метрики: FDR (средний FDP по сценариям), ложные тревоги на окно, вероятность хотя бы
одной ложной тревоги в окне, MTFA, доля пропущенных дрейфов (MDR), средняя задержка
(MTD) и «шагов на старой модели после дрейфа» — задержка, где пропуск считается до
конца потока. Последняя метрика — прямая цена задержки в прикладном смысле.

## Соответствие плану заявки

| Этап заявки | Сделано в MVP | Осталось |
|---|---|---|
| 4 базовых детектора | PH, DDM, ADWIN, KS; PH и DDM совпадают с river | ADWIN без сжатия окна; последовательный KS (IKS) |
| Калибровка блочным ресемплингом к единому FAR, отображение сигнал → p-значение | блочный, стационарный и AR-sieve бутстреп; хвостовая экстраполяция; проверка равномерности (эксп. 1) | поправка на изменчивость оценки нуля (Wu & Apley) |
| Синтетический стенд с известными точками сдвига | резкий и постепенный сдвиг, AR(1) + общий фактор, K до 500 | циклический дрейф; раздельно сдвиг p(X) и p(y\|X); 100 сценариев |
| Метрики MTFA, MDR, MTD, FAR | все, плюс FDR и цена задержки | R-measure |
| Онлайн-FDR: alpha-investing, LORD, SAFFRON | плюс LOND, BH и Бонферрони в окне | BatchBH/BatchSt-BH, LORD с затухающей памятью, e-детекторы (Dandapanthula–Ramdas) |
| Граница Парето по числу потоков | кривые компромисса по α при K = 10, 100, 500 (эксп. 3); точка безубыточности (эксп. 2) | по типу дрейфа и интенсивности |
| Реальные данные: Electricity, Airlines, Covertype, INSECTS | — | загрузчики и перенос выводов |

## Структура репозитория

```
src/driftfdr/
  streams.py       синтетические сценарии с известными точками сдвига
  detectors.py     PH, DDM, ADWIN, KS как векторизованные скоры
  bootstrap.py     блочный, стационарный, AR-sieve бутстреп
  calibration.py   нулевые распределения, p-значения, хвостовая экстраполяция
  online_fdr.py    правила принятия решений
  monitor.py       цикл мониторинга с переобучением по тревоге
  metrics.py       FDR, задержки, пропуски, цена задержки
experiments/       три эксперимента и общая обвязка
tests/             проверка совпадения с river, бутстрепа, калибровки, FDR-процедур
results/           CSV, таблицы и графики
```
